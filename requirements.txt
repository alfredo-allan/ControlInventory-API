# Backend Flask do ControlInventory — persistência via MySQL (PythonAnywhere)
# ou SQLite (dev local).
#
# IMPORTANTE (corrigido em 2026-10-13): este arquivo era gerado com `pip
# freeze` direto no sandbox de desenvolvimento, com versões EXATAS. Isso
# quebrou na primeira instalação de verdade fora daqui: o sandbox usa um
# índice de pacotes próprio que já tinha SQLAlchemy 2.1.4 disponível, mas
# no PyPI público (o que `pip install` usa no seu servidor/máquina) a
# versão estável mais recente da série 2.x ainda é a 2.0.x — 2.1 só existe
# em beta (2.1.0b1/b2/b3) lá. Resultado: "Could not find a version that
# satisfies the requirement SQLAlchemy==2.1.4" em qualquer instalação fora
# deste sandbox.
#
# Correção: troquei pins exatos por faixas mínimas (">=") nos pacotes que
# tinham esse risco, e mantive versão exata só nos 4 que o pip já tinha
# confirmado existir de verdade no PyPI (Flask, Flask-SQLAlchemy,
# Flask-Migrate, flask-cors — a instalação chegou a baixar esses antes de
# falhar no SQLAlchemy). As dependências transitivas do Flask (Werkzeug,
# Jinja2, MarkupSafe, blinker, click, itsdangerous, Mako) não precisam de
# pin manual — o próprio Flask/Flask-SQLAlchemy/Flask-Migrate/alembic já
# puxam versões compatíveis sozinhos; pin manual delas só reintroduz o
# mesmo risco de "versão que não existe fora do sandbox".
#
# O código não usa nenhuma sintaxe específica de SQLAlchemy 2.1 (é tudo
# `db.Column(...)` clássico, compatível com 2.0.x também), então essa
# troca não exige nenhuma mudança de código — só reflete melhor o que
# existe de verdade no PyPI público.
